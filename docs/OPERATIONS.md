# 운영 매뉴얼

운영 담당자가 "무엇을 자동으로 지켜 주고, 무엇을 사람이 해야 하는지"를 한눈에 보도록 정리한 문서다.

## 1. 자동으로 해 주는 것

| 항목 | 주기 | 알림 |
|---|---|---|
| 발송 대기열 처리, 예약 발송 | 매 분 (Cron) | — |
| **폰 상태 점검** | 5분마다 | 2시간 넘게 응답 없음·서버 연결 실패·최근 30분 발송 실패 3건 이상이면 **관리자 메일**(6시간에 한 번), 복구되면 복구 메일 |
| **오류 감시** | 상시 | 10분 안에 오류 5건 이상이면 **관리자 메일**(1시간에 한 번) |
| **발송 실패 자동 재시도** | 실패 즉시 | 최대 3번(2분, 10분 뒤). 잘못된 번호·인증 오류(400/401/403 등)는 재시도 없이 바로 "못 보냄" |
| **전달 결과 반영** | 폰이 보내는 이벤트(`sms:sent/delivered/failed`) + 2분마다 서버 조회로 보완 | 전달 실패면 자동 재시도 대기로 전환 |
| **새 답장 알림** | 답장이 올 때 | 알림을 켠 사용자에게 메일(내용 없이 링크만, 5분에 한 번), 화면 메뉴에 안 읽은 개수 |
| **자동 리마인드** (면접 안내별 선택) | 5분마다 확인 | 참석자에게 전날 17시·당일 8시 각 한 번(08~21시만) |
| **답 없으면 한 번 더** (면접 안내별 선택) | 10분마다 확인 | 보낸 지 24시간(면접이 가까우면 3시간 전, 최소 2시간 뒤) 지나도 답 없는 사람에게 한 번(09~21시만, 면접 1시간 전부터 안 보냄) |
| **일정 확정 문자** (일정 고르기 안내) | 번호 답장이 올 때 | 고른 일정을 바로 안내(같은 번호를 다시 보내면 안 보냄) |
| 개인정보 파기(보관기간 만료), 세션/제한 기록 정리 | 매 시 정각 | — |

- 알림 수신자: **관리자 권한 + 이메일 인증이 끝난 계정** 전원. 관리자 이메일을 꼭 등록해 둘 것.
- 알림 메일이 안 가면 `RESEND_API_KEY` / `MAIL_FROM` 설정을 확인한다(`docs/ACCOUNTS.md`).

### 폰 상태 판정

| 상태 | 기준 | 화면 | 메일 |
|---|---|---|---|
| 정상(ok) | 최근 15분 안에 폰이 응답 | 홈에 "폰 정상 · 마지막 응답 …" | — |
| 응답 늦음(warn) | 15분~2시간 응답 없음 | 홈에 파란 안내 | — |
| 확인 필요(down) | 2시간 초과 / 서버 연결 실패 / 폰 미등록 / 최근 실패 다수 | 홈에 빨간 경고, 설정 카드 배지 | **발송** |

> **중요**: 폰은 문자가 올 때만 서버와 통신하면 "응답 늦음"으로 보일 수 있다(문자를 보내면 폰이 깨어나 정상 동작한다).
> 상태를 정확히 보려면 폰 SMSGate 앱 **Settings → Ping → Interval (seconds)** 를 `300` 정도로 설정한다(배터리를 조금 더 쓴다).

수동 점검: 설정 → **시스템 상태 → 지금 점검하기**.

### 전달 결과의 의미

| 표시 | 뜻 |
|---|---|
| 보냄 | 문자 서버가 접수했고 폰이 통신사로 내보냈어요 |
| 전달됨 / ✓ 전달 | 통신사·상대 단말이 **전달 확인**을 준 경우에만 표시돼요 |
| 전달 실패 / 못 보냄 | 폰 또는 통신사가 실패를 알렸어요 (자동 재시도 3번 후 "못 보냄") |

> 많은 통신사/요금제는 SMS 전달 확인을 주지 않아서 대부분 "보냄"으로 남는다. 이는 정상이다. 운영 환경 시험에서도 서버 상태가 `Sent` 에서 `Delivered` 로 바뀌지 않았다.
> 폰 설정에 "전달 보고서(Delivery report)" 옵션이 있으면 켜 두면 도움이 될 수 있다.

웹훅(전달 결과 이벤트)을 받으려면 폰 연결 후 설정에서 **"답장·전달 결과 받기 다시 설정"** 을 한 번 눌러야 한다(코드 업데이트 후 1회).

## 2. 배포

```bash
npm run deploy              # 테스트 → 원격 DB 마이그레이션 → Worker 배포 → /healthz 확인
npm run deploy -- --dry-run # 실행 없이 순서만 확인
```

- 마이그레이션이 **코드 배포보다 먼저** 적용된다. 마이그레이션이 실패하면 배포하지 않는다.
- 배포 후 `/healthz`(DB 포함)가 정상이어야 성공으로 끝난다. 실패하면 `npx wrangler rollback`.
- `npm run deploy:raw` 는 검사 없이 배포한다. **긴급한 경우 외에는 쓰지 않는다.**
- GitHub Actions: 푸시/PR 마다 **CI(테스트)** 가 돌고, **Deploy** 워크플로는 수동 실행이다.
  Deploy 를 쓰려면 저장소 시크릿 `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` 를 등록한다.

## 3. 백업과 복구

### 정기 백업(내보내기)

```bash
npm run backup                          # backups/ 에 SQL 저장, 최근 8개 보관
npm run backup -- --dir D:\백업 --keep 12
```

- **주 1회** 실행하고, 큰 면접 안내를 보내기 전에도 한 번 한다.
- 파일에는 이름·전화번호·문자 내용이 들어 있다. 외부 반출 금지, 보관 기간이 지나면 삭제한다. (`backups/` 는 git 에 올라가지 않는다)
- 자동화: Windows 작업 스케줄러에 `npm run backup` 을 주 1회로 등록한다(프로젝트 폴더에서 실행).

### 시점 복구 (D1 Time Travel, 최근 30일)

```bash
npx wrangler d1 time-travel info interview-sms                       # 현재 북마크 확인
npx wrangler d1 time-travel restore interview-sms --timestamp=2026-10-15T09:00:00+09:00
# 또는 --bookmark=<북마크>
```

- 복구하면 **지정 시점 이후의 변경(발송 기록, 가입 등)이 사라진다.** 실행 전에 `npm run backup` 으로 현재 상태를 먼저 내보낸다.
- 복구 후 `/healthz` 와 로그인, 발송 시험으로 확인한다. 복구 자체를 되돌릴 때는 복구 직전 북마크로 다시 restore 한다.
- 분기마다 **복구 연습**(별도 DB 에 backup 파일 import 후 로그인/조회 확인)을 권한다.

### 백업 파일로 다른 DB 에 복원

```bash
npx wrangler d1 create interview-sms-restore-test
npx wrangler d1 execute interview-sms-restore-test --remote --file=backups/<파일>.sql
```

## 4. 장애 대응 순서

| 증상 | 확인 | 조치 |
|---|---|---|
| 폰 경고 메일 | 폰 전원·인터넷, SMSGate 앱 서비스 시작(Online) | 앱 재시작 → 설정 "연결 확인" → "받기 시험" |
| 문자가 안 나감 | 홈 폰 상태, 캠페인 "못 보냄" 건수 | 폰 정상화 후 "답 없는 사람에게 다시 보내기" |
| 답장이 안 들어옴 | 폰 상태, 설정의 "답장 받기 다시 설정", 폰 문자앱 채팅(RCS) 꺼짐 | `docs/RUNBOOK.md` |
| 오류 알림 메일 | 설정 → 시스템 상태의 최근 오류, `npx wrangler tail` | 직전 배포가 원인이면 `npx wrangler rollback` |
| 로그인/가입 메일 안 옴 | 스팸함, Resend 대시보드 | `docs/ACCOUNTS.md` |
| 사이트 접속 불가 | `https://interview.bigbears.me/healthz` | Cloudflare 상태, `wrangler deployments list` |

## 5. 정기 점검 체크리스트

- [ ] 주 1회: `npm run backup`, 설정 → 시스템 상태에서 오류 확인
- [ ] 월 1회: 관리자 이메일 수신 확인(알림이 오는지), 인증 대기 계정 정리, 사용하지 않는 계정 중지
- [ ] 분기 1회: 복구 연습, 비밀번호 약한 계정 점검, 폰 앱 업데이트 확인
- [ ] 면접 안내 대량 발송 전: 폰 정상 확인, 백업, 본인 번호 1건 시험
