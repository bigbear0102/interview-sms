# 답장 해석 규칙

구현: `src/parser.js` `parseReply()` / 테스트: `test/parser.test.js`

## 순서
1. 공백·문장부호 제거, 소문자화, 전각 숫자 변환
2. 메시지가 `1`이면 참석, `2`이면 불참
3. **부정 키워드 포함 → 불참** (먼저 검사: "불참"에 "참"이 들어있기 때문)
3-1. 질문형이면 → 확인필요
4. 긍정 키워드 포함 → 참석
5. 짧은 약어(ㅇㅇ, ok, yes / ㄴㄴ, no)
6. 그 외 → **확인필요(unclear)** — 관리자가 화면에서 수동 확정

## 키워드
- 부정: 불참, 미참, 불가, 못 가, 안 갈, 참석 못/안/어렵, 어렵, 힘들, 곤란, 취소, 포기, 죄송, 아니요 …
- 긍정: 참석, 참여, 갈게, 가겠, 가능, 방문, 네, 예, 넵, 알겠 …

## 알려진 한계
- 질문형(`?`, ~한가요/~되나요 등)은 부정 표현이 없으면 `unclear`로 보낸다. 긍정 의사가 담긴 질문("참석 가능한가요?")도 확인필요가 된다.
- 부정과 긍정이 함께 있으면 **부정이 이긴다**(보수적: 불참으로 오인해도 재확인하면 되지만, 참석으로 잘못 확정하면 놓치기 쉬움).
- 사진/이모티콘/영어 장문은 해석하지 못하고 `unclear`.
- 관리자가 수동 확정한 건(`manual=1`)은 이후 답장으로 덮어쓰지 않는다. **예외(2026-10-17 QC)**: 불참으로 읽히는 답장이나 일정 변경 요청이 오면 "확인 필요"로 올리고 수동 표시를 푼다(취소를 놓치고 리마인드를 보내지 않게).

## 되돌아온 문자는 답장이 아니다
같은 번호에서 들어온 문자가 **30분 안에 우리가 그 번호로 보낸 문자(면접 안내·확정·리마인드·직접 문자)와 내용이 같으면** 해석하지 않고 `echo`(화면: "보낸 문자가 되돌아옴")로만 남긴다. 문자 보내는 폰 자기 번호로 시험할 때 보낸 문자가 그대로 수신되어, 문구 속 "불참" 때문에 불참으로 바뀌던 문제(2026-10-17 실제 시험)를 막는다.

## 일정 고르기 안내의 답장 (`parseSlotReply`)
면접 안내를 "면접 일정을 골라 달라고 해요"로 만들면 답장의 **숫자는 일정 번호**다(`1`=참석, `2`=불참 규칙을 쓰지 않는다).
1. 날짜·시각 숫자(`10/21`, `14시`, `14:00`, `21일`)는 지우고 남은 숫자를 본다.
2. 번호가 **하나**이고 1~후보 수 안이면 → 그 일정으로 **참석**(면접일시에 그 일정이 들어가고 확정 문자가 간다).
3. 번호와 부정 표현이 함께 있거나("2번은 어렵고 1번"), 번호가 여러 개이거나, 없는 번호면 → **확인필요**.
4. 번호 없이 부정 표현 → **불참**. 번호 없이 긍정("네")은 이미 일정을 고른 사람이면 참석 유지, 아니면 확인필요.
5. 담당자가 그 사람만 새 일정으로 다시 안내했다면(`template_override`) 이후 답장은 일반 규칙을 쓴다.

## 일정 변경 요청 표시 (`isRescheduleRequest`)
참석/불참 판정과 **따로**, 답장에 변경·바꾸·다른 날/시간·미루·연기·조정·다음 주 같은 말이 있으면 `reply_kind='reschedule'`로 표시한다.
판정이 **불참**이면 **확인필요**로 바꾼다("죄송한데 다음 주로 미룰 수 있을까요?"는 불참이 아니라 담당자가 확인할 일, 2026-10-17 실제 시험). 그 밖의 판정은 그대로 둔다. 화면에 "일정 변경 요청" 뱃지·탭이 생기고, 담당자는 "새 일정으로 다시 안내"로 그 사람에게만 다시 보낸다.

## AI 로 한 번 더 보기 (`src/reply-ai.js`, NVIDIA, 2026-10-17)
규칙 결과가 **확인필요**이거나, **불참**인데 문장이 긴 경우("늦게 답해서 죄송해요 참석할게요")에는 저장 뒤 NVIDIA AI(`openai/gpt-oss-20b`)에 한 번 더 묻는다. 시크릿 `NVIDIA_API_KEY`가 없으면 규칙만 쓴다.
- AI에 보내는 것은 답장 원문, 일정 후보, 정해진 일시, 오늘 날짜예요. 이름과 전화번호는 보내지 않는다.
- 확신도가 0.8 이상일 때만 적용한다. 규칙의 불참을 참석으로 바꾸려면 0.9 이상이어야 한다.
  - **참석 + 후보 번호**: 그 일정으로 확정하고 확정 문자를 보낸다("22일 10시요", "목요일 두시", "마지막 시간").
  - **참석** (정해진 일정): 참석으로 바꾼다.
  - **불참** ("다른 데 붙었어요"): 불참으로 바꾼다.
  - **후보에 없는 날짜**: 일정 변경 요청으로 표시한다.
  - **질문**: 확인필요로 둔다.
- 결과는 `candidates.ai_note`에 "AI: 참석(1번 일정) · 요약" 형식으로 남고, 받은 답장 아래에 보인다. 실패, 시간 초과, 낮은 확신이면 바꾸지 않는다.
- 그 사이 새 답장이 오거나 담당자가 직접 정한 건은 덮어쓰지 않는다. 감사 로그 `reply.ai`에는 결과만 남긴다(개인정보 없음).
- 실제 API 시험: 2026-10-17 가짜 지원자 답장 15건 모두 정답, 1건당 1.6~3.9초. 단위 시험은 가짜 AI만 쓴다.
- **일정 변경 요청**에 원하는 일시가 있으면 `ai_wanted`에 넣어요. 이 값은 "새 일정으로 다시 안내" 칸에 미리 채워지고, 보내기는 담당자가 해요.
- **질문**이면 보낸 안내 문자에 있는 정보만으로 답장 초안(`ai_draft`)을 만들어요. AI에 보내기 전에 이름과 번호는 가려요. 안내에 답이 없으면 초안을 만들지 않아요(주차, 시급 등). 보내기는 담당자가 해요.
- **날짜 계산은 코드가 해요** (`ai.js` `resolveWhen`):
  - AI는 요일이나 "다음주" 계산을 자주 틀려요(실제 시험: 토요일 기준 "다음주 월요일"을 금요일로 계산).
  - 그래서 AI에게서는 표현 조각(날짜 / 요일+주 / 내일·모레 / 시각)만 받고, 날짜는 코드가 계산해요.
  - 원문과도 다시 맞춰 봐요. 요일·"다음주"·"내일"은 원문에서 직접 읽고, 날짜와 요일이 맞지 않거나 원문에 날짜 표현이 없거나 "N시"가 다르면 버려요.
- 면접 안내와 연결되지 않은 문자는 종류(지원 문의 / 면접 관련 / 업무 연락 / 광고·스팸 / 기타)와 요약만 `inbound.ai_note`에 남겨요(문자함).
