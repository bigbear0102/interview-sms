# 채용 워크플로우 설계 v2 — "자동이 기본"에 맞춘 화면 재설계 (2026-10-18)

- **근거**
  - CI `UI shots`(SHOTS_ALL) 30개 화면을 PC 1280px·모바일 390px로 검토했어요.
  - 운영 데이터: 새 지원 127건, 연락처 22건, 이력서 저장 0건.
  - 10/17 이후 바뀐 기능: 그룹웨어 직접 수집, 연락처·이력서 자동 가져오기, AI 답장 해석, 별점, AI 찾기, 진행 카드.
- **v1**(`docs/WORKFLOW-v1.md`)은 수동 수집을 전제로 설계해서 모두 반영했어요. v2는 **사람이 하던 일을 시스템이 하게 된 뒤** 화면이 여전히 수동 흐름을 보여 주는 문제를 고쳐요.
- 화면 규칙은 `docs/UX.md`, 시각 토큰은 `DESIGN.md`를 따라요.

## 1. 설계 원칙 (v2에서 추가·강화)

1. **자동으로 된 일은 조용히, 사람이 할 일만 크게.** 상태 설명 문장 대신 숫자와 할 일 버튼으로 보여 줘요. 안내·경고 문구는 다음 행동이 바뀔 때만 써요(사용자 피드백, 2026-10-18).
2. **같은 정보는 한 화면에 한 번만.** 숫자와 연결 상태를 여러 곳에 반복하지 않아요.
3. **판단에 필요한 정보는 판단하는 자리에.** 등록할지 고르는 카드에 이력서 요약을, 출석을 기록하는 자리에 별점을 둬요.
4. **찾기는 한 곳.** 이름·번호를 넣으면 바로 찾고, 문장을 넣으면 AI가 조건으로 바꿔 찾아요.
5. **모바일 첫 화면에 첫 할 일이 보여야 해요.** 세로 900px 안에 첫 카드나 첫 버튼이 나와야 해요.

## 2. 목표 워크플로우 (채용담당자 기준)

```
① 지원 메일 ─▶ ② 연락처·이력서 ─▶ ③ 검토 ─▶ ④ 면접 대상 선택 ─▶ ⑤ 안내 ─▶ ⑥ 답장 ─▶ ⑦ 리마인드 ─▶ ⑧ 당일 ─▶ ⑨ 결과
   자동(1분)      자동(확장, 5분 재시도)   사람        사람(찾기·별점)        사람     자동+AI, 예외만    자동         사람(출석·별점)  사람
```

| 단계 | 사람이 하는 일 | 시스템이 하는 일 | 화면 | 끝난 상태 |
|---|---|---|---|---|
| ① | 없음 | 그룹웨어 POP3로 1분마다 수집, 공고 원가중심점 자동 분류·AI 추천 | — | 새 지원 생성 |
| ② | 없음(PC 크롬만 켜 둠) | 연락처+이력서 전체 저장, 빠진 건 5분마다 다시 시도 | 새 지원 상단 **한 줄 상태** | 연락처·이력서 있음 |
| ③ | 카드의 **이력서 요약**을 보고 [등록] 또는 [무시] (자동 등록이면 [무시]만) | 같은 공고 일괄 분류 | 새 지원 | 지원자 |
| ④ | 지원자에서 찾기(이름·조건·문장) → 체크 | 별점 높은 순, 노쇼·블랙리스트 표시 | 지원자 | 대상 선택 |
| ⑤ | 일시·후보 일정 → 문구(AI 점검) → 보내기 | 명단 칸·일시 AI 정리, 진행 카드 | 면접 안내 만들기 | 발송 |
| ⑥ | **확인 필요·질문 초안·일정 변경만** 처리 | 규칙+AI 자동 분류, 확정 문자, 일반 문자 분류 | 홈 → 면접 안내 상세(처리 탭) | 모두 결정됨 |
| ⑦ | 없음 | 전날 17시·당일 8시·답 없으면 한 번 더 | — | 발송 |
| ⑧ | 출석/노쇼 + **그 자리에서 별점** | — | 오늘 면접 | 출석 기록·별점 |
| ⑨ | 합격·불합격 → 결과 문자 | 노쇼 누적 → 블랙리스트 후보 | 면접 안내 상세 | 결과 안내 |

| # | 문제(근거) | 해결 | 완료 기준 |
|---|---|---|---|
| P0-1 | **새 지원 첫 카드가 모바일 900px 아래**에 있어요. 상단에 배너 3개(이력서 없음 / 연락처 대기 빨강 / 공고 정리)와 상태 알약, 숫자 카드 4개가 쌓여 있어요(m-inbox). | 상단은 **상태 줄 1개 + 필터 칩 1줄**만 남겨요. 상태 줄 예: "● 자동 수집 켜짐 · 연락처 대기 3 · 이력서 대기 2 · 공고 정리 1 →". 숫자 카드 4개는 필터 칩(대기 6 · 연락처 필요 5 · 분류 필요 2 · 등록 가능 1)으로 바꿔요. | 모바일 첫 카드가 600px 안에 보여요 |

### P1 — 효율과 일관성

| # | 문제 | 해결 |
|---|---|---|
| P1-1 | 찾기 진입점이 둘이에요: 지원자 검색창과 "AI 찾기" 탭. | 검색창 하나로 합쳐요. 이름·번호면 바로 찾고, 문장("안양 사무 20대")이면 AI가 조건을 정해서 별점 순으로 보여 줘요. 위에 해석한 조건을 칩으로 보여 주고 지울 수 있게 해요. "AI 찾기" 탭은 없애요. |
| P1-2 | 새 지원 카드마다 연락처 입력칸과 [등록]이 있어 카드가 높아요(PC 210px). 연락처가 자동이 된 뒤로는 예외용이에요. | 연락처가 있으면 [등록]만 보여요. 연락처 직접 입력은 "직접 입력"을 펼쳤을 때만 보여요. 카드 높이 목표는 140px 이하예요. |
| P1-3 | 별점을 상세 화면에 가서야 줄 수 있어요. 별점은 면접 직후에 가장 정확해요. | **오늘 면접**의 출석 버튼 옆에 별 5개를 둬요. 면접 안내 상세의 결과 칸 옆에도 둬요. |
| P1-4 | 면접 안내 상세에서 같은 숫자가 세 번(숫자 카드, 막대 범례, 필터 탭) 나오고, "모두 보냈어요. 답장이 오면…" 안내도 있어요. | 숫자 카드를 지우고, 막대 + 필터 탭(숫자 포함)만 남겨요. 상태 안내는 보내는 중이거나 실패가 있을 때만 보여요. 처리할 답장이 있으면 그 탭이 기본으로 선택돼요. |
| P1-5 | 홈의 "이번 달 시스템이 대신한 일"이 큰 카드예요(월 1회 보는 정보). | 홈 맨 아래 한 줄 요약("이번 달 약 32분 절약 · 자세히")으로 줄여요. |

| P1-7 | 면접 안내 상세의 행 동작이 섞여 있어요: "바꾸기" 링크, 결과 고르기 칸, 참석/불참 버튼. | 행 끝에 상태에 맞는 동작 하나만 둬요(확인 필요 → 참석/불참, 변경 요청 → 다시 안내, 참석 → 결과·별점). 나머지는 "⋯" 메뉴로 옮겨요. |

## 4. 정보 구조(v2)

```
홈 ── 오늘 할 일(0이면 숨김) · 오늘 면접 · 면접 현황 · (한 줄) 절약 시간
지원자 ─┬ 새 지원 (상태 줄 · 필터 칩 · 이력서 요약 카드 · 등록/무시)

        ├ 공고 정리 (AI·이력 추천)
        └ 연결 설정 (그룹웨어 · 확장 · 관리자)

        └ 오늘 면접 (출석/노쇼 + 별점)
문자함 ─ 받은/보낸/예약 (일반 문자 AI 분류)
설정 ── 폰·사용자·부서·감사 기록
```

## 5. 고치고 반영하는 방법 (항목마다 같은 순서)

1. **기준 확인**: 이 문서의 항목 번호, 완료 기준, 영향받는 화면을 정해요.
2. **미리보기 데이터 준비**: `deploy/dev/render-preview.mjs`에 그 상태가 보이는 데모 데이터를 넣어요(예: 연락처 대기·이력서 있는 카드, 처리할 답장이 있는 안내). 데모에 없는 상태는 검토할 수 없어요.
3. **구현**: 브랜치를 만들고 코드를 고쳐요. 문구는 `docs/GUIDE.md`와 함께 바꾸고, 쓸데없는 안내 문구는 넣지 않아요.
4. **자동 시험**: `npm test`(구조 시험의 탭·문구 포함). 확장을 건드리면 CI "Extension test"까지 돌려요.
5. **화면 검토**: CI "UI shots"를 PC·모바일로 캡처해요(가로 넘침이 있으면 실패). 캡처를 받아 디자이너 관점으로 봐요: 첫 화면에 할 일이 보이는지, 중복이 없는지, 모바일 순서가 맞는지.
6. **병합·배포**: main에 병합하고 `npm run deploy`(마이그레이션 포함) 후 `/healthz`를 확인해요.
7. **운영 확인**: 운영 데이터로 해당 화면 숫자를 대조하고, 확인하지 못한 것은 HANDOFF에 적어요.
8. **기록**: `HANDOFF.md`(상태), `DECISIONS.md`(왜), 이 문서의 진행 상태를 갱신하고 main에 푸시해요.
