# 채용 워크플로우 설계 (UX/UI 검토, 2026-10-17 배포 전)

근거: 데모 데이터로 모든 화면(25개)을 PC 1280px·모바일 390px 로 캡처해 검토(CI `UI shots`, `SHOTS_ALL=1`), 운영 데이터 집계, 2026-10-17 운영 실제 시험.
이 문서는 **무엇을 왜 바꾸는지**의 기준이다. 화면 규칙은 `docs/UX.md`, 시각 토큰은 `DESIGN.md`.

## 1. 누가, 어디서, 무엇을

| 사용자 | 기기·상황 | 하루의 핵심 일 |
|---|---|---|
| **채용담당자**(주 사용자, 부서별) | 사무실 PC(오전·오후 몰아서), 이동 중 휴대폰(답장 확인·짧은 처리) | 새 지원 정리 → 면접 대상 골라 안내 → 답장 처리 → 면접 당일 출석 기록 → 결과 안내 |
| 전체 관리자 | PC | 폰·사용자·부서·연결 설정, 블랙리스트 승인 |
| (향후) 사업장 담당자 | 현장 휴대폰 | 당일 출석·노쇼 기록 — 지금은 없음, 3장 P2 |

설계 원칙: ① 화면은 **일의 순서**대로 ② 첫 화면은 **지금 할 일**이 숫자와 함께 ③ 사람은 **이름**으로 본다(번호만 보여 주지 않는다) ④ 자동으로 한 일은 표시하고 사람이 할 일만 버튼으로 ⑤ 모바일은 **한 손·세로 스크롤 한 번**에 핵심 동작.

## 2. 목표 워크플로우 (채용담당자 기준)

```
① 새 지원 ─▶ ② 정리·등록 ─▶ ③ 면접 안내 ─▶ ④ 답장 처리 ─▶ ⑤ 리마인드 ─▶ ⑥ 면접 당일 ─▶ ⑦ 결과
   자동         공고당 1회       고르기→보내기      자동 분류+예외만      자동            출석/노쇼        결과 문자
```

| 단계 | 담당자가 하는 일 | 시스템이 하는 일 | 화면 | 끝난 상태 |
|---|---|---|---|---|
| ① 새 지원 | (없음) | 그룹웨어 메일 수집(확장 → 자동 전달 예정), 지원자 카드 생성 | 새 지원 | 카드 생성 |
| ② 정리·등록 | 새 공고면 원가중심점 1번 지정, 거를 사람 "무시" | 같은 공고 자동 분류, 연락처 요청 → 확장이 채움, 자동 등록(설정 시) | 새 지원 · 공고 정리 | 지원자로 등록 |
| ③ 면접 안내 | 지원자 체크 → "면접 안내 만들기" → 일시(또는 후보 일정) → 보내기 | 명단 채움, 블랙리스트 참고 표시, 발송·재시도 | 지원자 → 면접 안내 만들기 | 문자 발송 |
| ④ 답장 처리 | **확인 필요·일정 변경 요청만** 처리 | 참석/불참/번호 자동 분류, 확정 문자, 되돌아온 문자 무시, 답 없으면 한 번 더 | 면접 안내 상세 · 홈 | 모두 참석/불참 |
| ⑤ 리마인드 | (없음) | 전날 17시·당일 8시 | — | 발송 |
| ⑥ 면접 당일 | 오늘 면접자 출석/노쇼 기록 | — | **(없음 → 신설 "오늘 면접")** | 출석 기록 |
| ⑦ 결과 | 합격·입사·불합격 기록 → 결과 문자 | 결과 문자 1회, 노쇼 누적 → 블랙리스트 후보 | 면접 안내 상세 · 지원자 | 결과 안내 |

**지원자 진행 단계(화면 표시 기준, 저장 없이 계산)**: 면접 안내 전 → 보낼 예정 → 답 없음 / 확인 필요 / 불참 / 참석 예정 → 출석 / 노쇼 → 합격 / 입사 / 불합격.

## 3. 검토 결과와 해결

### P0 — 배포 전에 반드시 (깨짐·핵심 흐름 단절)

| # | 문제(근거) | 해결 |
|---|---|---|
| P0-1 | **모바일 새 지원 화면이 가로로 넘친다**(캡처 폭 410px > 390px). 머리말 오른쪽 연결 상태 문구가 줄바꿈되지 않음 → 화면 전체가 좌우로 흔들림 | 연결 상태를 머리말 아래 한 줄로(모바일), 문구 줄바꿈 허용. 모든 화면 캡처 폭 = 390 을 CI 에서 검사 |
| P0-2 | **모바일 지원자 상세의 버튼 3개가 동그랗게 찌그러져** "면접 안내 만들기"가 세로로 쪼개짐 | 모바일은 주 버튼 1개 전체 폭 + 보조 2개 반반. "관리"(합치기·삭제)는 이력 아래로 |
| P0-3 | **면접 당일 할 일이 없다**. 출석 기록은 해당 안내 상세 맨 아래 표에서 행마다 골라야 함(모바일 2,300px 스크롤). 결과 기록 0건의 원인 | **"오늘 면접"** 화면 신설: 오늘 면접일시인 참석자(모든 안내 합침) 시간순, 행마다 큰 [출석] [노쇼] 버튼. 홈 할 일 "오늘 면접 N명" |
| P0-4 | **면접 안내 상세에서 할 일이 맨 아래**: 숫자 → 면접 결과 → 결과 문자 → 자동 문자 → 사업장 표 → (마지막) 사람별 표. 면접 전인데 "면접 결과 0/0" 이 먼저 보임 | 순서: 상태·숫자 → **처리할 사람(확인 필요·변경 요청·답 없음 탭이 기본 선택)** → 사람별 표 → 사업장 표 → 설정(자동 문자·보낸 문자·결과 문자는 접기). 결과 섹션은 결과가 1건 이상이거나 면접일이 지났을 때만 |
| P0-5 | **문자함이 번호만 보여 준다**(010-2000-1007 …). 누가 보냈는지 알 수 없음. 시스템이 보낸 확정 문자가 "예약됨 + 예약 취소" 로 보여 사람이 보낸 예약과 구분 안 됨 | 번호 옆 **이름**(면접 대상·지원자 매칭) + 어느 면접 안내의 답장인지 링크. 자동 문자는 "자동 · 확정 문자/리마인드/결과" 뱃지, 1분 안에 나가는 건 "곧 보냄"(취소 버튼 숨김) |
| P0-6 | **모바일 하단 탭에 지원자 관리가 없다**(더보기 안). 채용 흐름의 시작점이 숨어 있고 "보내기"(단건 문자)가 주 탭 | 하단 탭: **홈 · 지원자 · 면접 · 문자함 · 더보기**. 문자 보내기는 문자함 오른쪽 위 "새 문자"와 홈 버튼으로 |

### P1 — 배포 직후 1~2주 (효율·혼란 줄이기)

| # | 문제 | 해결 |
|---|---|---|
| P1-1 | **사람 목록이 둘**: "지원자"와 "면접 이력"(같은 사람, 다른 표·다른 기준) | 면접 이력을 지원자 목록의 열(진행·안내 횟수·노쇼)과 필터("노쇼 있음")로 합치고 탭에서 뺌. 등록 안 된 면접 대상은 연결 설정의 자동 등록으로 해결 |
| P1-2 | **홈이 길다**(PC 2,500px): 오늘 할 일 / 면접 현황 표 / 면접 안내 목록 / 최근 받은 문자 / 오늘의 숫자 / 이번 달 대신한 일 — 숫자 중복 | 홈 = 오늘 할 일 + 오늘 면접 + 이번 주 면접 현황(요약). 받은 문자·오늘의 숫자는 문자함으로, 절약 시간 카드는 월 1회 보는 정보라 접기 |
| P1-3 | 홈 주 버튼이 "문자 보내기" | 주 버튼 "면접 안내 만들기", 보조 "새 지원 보기" |
| P1-4 | 사람별 표의 [참석][불참] 버튼이 이미 참석인 행에도 늘 보임, 상태별로 필요한 동작이 다름 | 상태별 1~2개만: 확인 필요 → [참석][불참], 변경 요청 → [일정 다시 안내], 참석 → (면접 후) 결과, 답 없음 → (없음, 위의 "다시 보내기") |
| P1-5 | 연결 설정이 여전히 "그룹웨어 비밀번호를 확장에 저장"을 1·2단계로 안내. 결정은 **메일 자동 전달** | 1단계 "그룹웨어 자동 전달 규칙"(주소 복사 + 그림 안내), 2단계 "연락처용 확장 설치", 그룹웨어 계정 등록은 "다른 방법"으로 |
| P1-6 | 자동 문자 토글이 모바일에서 설명이 토글 아래로 떨어져 읽기 어려움 | 토글을 오른쪽 끝, 제목·설명을 왼쪽 두 줄로(설정 목록 패턴) |
| P1-7 | 이름: 브랜드가 "문자 관리"인데 실제는 채용(지원자·면접) 시스템 | **사용자 결정 필요**: "채용 관리" 등으로 바꿀지. 바꾸면 로그인·소개·메일 문구 함께 |

### P2 — 나중에

- 사업장 담당자용 당일 출석 기록(링크로 접속, 로그인 없이 그날 명단만) — P0-3 의 "오늘 면접" 화면을 재사용.
- 연락처를 회사 서버에서 무인으로(브랜치 `company-server-agent`).
- 일정별 정원 — 필요 없다고 결정(2026-10-17).

## 4. 정보 구조(목표)

```
홈            오늘 할 일(확인 필요 답장 · 오늘 면접 · 등록할 새 지원 · 연락처 대기) · 이번 주 면접 요약
지원자        새 지원 | 지원자(진행 단계·면접 이력 포함) | 공고 정리 | 연결 설정
면접          면접 안내 목록 | 오늘 면접(신설) | 면접 안내 만들기
문자함        받은 | 보낸 | 예약 · 새 문자(=문자 보내기)
설정(관리자)  문자 보내는 폰 · 시스템 상태 · 사용자 · 부서
```
하단 탭(모바일): 홈 · 지원자 · 면접 · 문자함 · 더보기(설정·내 계정·폰 안내·기록).

## 5. 배포 전 확인 목록 (P0 반영 후)

- [ ] 모든 화면 캡처 폭 = 1280 / 390(가로 넘침 없음), 스크립트 문법 오류 없음(테스트)
- [ ] 흐름 A: 새 지원 → 분류 → 연락처 → 등록 → 지원자 체크 → 면접 안내(정해진 일시) → 발송 → "참석" → 전날·당일 리마인드 → 오늘 면접에서 출석 → 합격 → 결과 문자
- [ ] 흐름 B: 일정 고르기 → 번호 답장 → 확정 문자 → 변경 요청 → 다시 안내 → 참석
- [ ] 흐름 C: 답 없음 → 한 번 더 → 노쇼 3회 → 블랙리스트 후보 → 등록 → 다음 면접 안내 만들 때 참고 표시
- [ ] 문자함에서 모든 답장이 이름과 함께 보이고, 자동 문자는 자동으로 표시
- [ ] 모바일 한 손: 홈 → 확인 필요 처리, 오늘 면접 출석 기록이 스크롤 1번 안
- [ ] 실제 폰 시험은 관리자 번호로만
