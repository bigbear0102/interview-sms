# 설계 결정 기록 / 로드맵

## 결정
| # | 결정 | 이유 |
|---|---|---|
| 1 | 게이트웨이는 android-sms-gateway **로컬 서버 모드** | 현재 PC 자체 호스팅. 제3자 서버를 거치지 않아 개인정보 노출이 적음 |
| 2 | 답장 방식은 **자유 문구 해석**(링크 클릭 아님) | 요구사항: "참석/불참/미참 등 다양한 문구" |
| 3 | Node 내장 SQLite, 외부 npm 의존성 없음 | 설치·인수인계가 쉽고 D1(SQLite 계열)로 이전 용이 |
| 4 | 서버 렌더링 HTML, 프레임워크 없음 | 단순함. 규모가 커지면 분리 |
| 5 | 사업장은 CSV의 `사업장` 컬럼으로 자동 분리 | 수천 개 사업장을 사전 등록 없이 처리 |
| 6 | 보관기간은 캠페인별 설정, 만료 시 개인정보만 파기하고 통계 유지 | 법적 보관기간은 법무 확인 후 기본값(90일) 조정 |
| 7 | 인증은 아이디/비밀번호(scrypt) + 부서 단위 권한 | 요구사항 |

## 미검증/주의
- **실제 폰 연동 미검증**: 발송 API 경로(`/message`), 웹훅 payload 필드는 공식 문서 기준으로 작성. 실제 폰으로 1차 시험 필요.
- 쿠키 `Secure` 플래그 미적용(HTTP 로컬 운영 기준). HTTPS 프록시/터널 뒤에서 운영하면 추가할 것.
- 법정 보관기간 기본값은 법무 확인 필요.
