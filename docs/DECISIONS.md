## 미검증/주의
- **실제 폰 종단 시험 전**: 게이트웨이 API 경로/응답, 웹훅 payload, 앱 QR 연결 방식은 문서 기준.
- 법정 보관기간 기본값은 법무 확인 필요.
- 무료 플랜 처리량 ≈ 25건/분. 대량(수천 건) 발송이 잦으면 유료 플랜 + `SEND_BATCH` 상향.
- 현재 Cloudflare 계정은 로그인된 wrangler 계정(`workers.dev` 서브도메인 `bigbears`)이다. 회사 도메인/계정으로 옮길 때는 `wrangler.jsonc`의 D1 id 와 시크릿을 새로 만든다.

## 운영 메모
- 기존 Cloudflare Worker `interview-sms`(workers.dev)와 D1 은 PC 이전 전 시험 배포본이다. 현재 운영 대상이 아니며 필요 없으면 삭제한다(`npx wrangler delete`, D1 삭제).
- Cloudflare 계정에는 다른 터널(`real-estate-dashboard`, `my-homelab-tunnel`, `oracle`)이 있다. `interview-sms` 터널만 사용하며 DNS 연결 시 반드시 **터널 UUID** 로 지정한다(이름 지정 시 기본 config 의 다른 터널로 연결될 수 있음).

## 2026-10-15 웹을 Cloudflare Workers 로 이전
- 도메인(`interview.bigbears.me`)은 DNS 를 바꾸지 않고 Worker route 로 가로챔. 웹훅 주소/토큰이 그대로라 폰 쪽 변경 없음.
- 데이터는 `deploy/cloudflare/export-to-d1.mjs` 로 SQLite → D1 이전, 시크릿은 `put-secrets.mjs`.
- **남은 PC 의존**: 게이트웨이 서버(Docker). 상시 서버(예: Cloudflare 계정에 터널이 있는 Oracle/홈서버, 또는 회사 서버)로 옮기면 PC 는 완전히 불필요.
- Workers 무료 플랜 발송 처리량 ≈ 25건/분(시간당 1,500건). 대량 발송이 잦으면 유료 플랜 + `SEND_BATCH` 상향.
- 회사 서버 이전 시 D1 → SQLite: `deploy/cloudflare/import-d1-export.mjs` (검증 완료).

## 2026-10-15 게이트웨이를 공개 클라우드(api.sms-gate.app)로 전환 + 종단간 암호화
- 사용자 결정: PC/서버 없이 운영. 대신 번호/내용이 제3자 서버를 거치므로 **앱의 passphrase 종단간 암호화**를 필수로 안내한다.
- 암호화 대상: 문자 내용(`textMessage.text`)과 받는 번호(`phoneNumbers`). 형식 `$aes-256-cbc/pbkdf2-sha1$i=<반복>$<salt>$<암호문>` (테스트로 앱 규격 복호화 검증).
- 한계: 폰이 서버로 올리는 **받은 문자(답장) 내용의 암호화 여부는 문서에 명시되지 않음**. 웹훅은 폰 → 우리 Worker 로 직접 가므로 공개 서버를 거치지 않는다.
- 기기 키 기반 E2E(RSA-OAEP, MGF1=SHA-1)는 WebCrypto 가 OAEP 와 MGF1 해시를 분리 지정할 수 없어 Workers 에서 구현 불가 → passphrase 방식 사용.
- 비용/성능: 필드당 PBKDF2 비용이 있어 Workers 무료 플랜(CPU 10ms)에서는 반복 횟수를 낮춰야 한다. 대량 발송은 유료 플랜 권장.

## 2026-10-15 PC 게이트웨이 중지
- 폰이 공개 서버로 이전되어 PC 의 게이트웨이/터널/웹 작업을 모두 중지(비활성화). 중지 후 연결 확인·받기 시험 통과.
- 컨테이너와 DB 볼륨은 롤백용으로 보존. 정리하려면 RUNBOOK 의 "PC 게이트웨이 중지 상태와 되돌리기" 참고.

## 2026-10-15 직원 회원가입(이메일 인증)
- 로그인은 이메일+비밀번호. 가입은 `@willvi.co.kr` 만, 이름·이메일·휴대폰·부서 입력, 메일 링크 인증 후 사용.
- 권한 2단계: 관리자(전체 수정) / 일반 사용자(가입 때 고른 부서 범위). 관리자는 사용자·부서·폰·권한을 모두 수정/삭제할 수 있다.
- 메일 발송은 교체 가능한 구조(`src/mailer.js`: Resend / Cloudflare Email Sending / 주입 함수). 발송은 BBform 과 같은 Resend 계정/도메인(mail.bigbears.me) 재사용으로 설정됨(2026-10-15). 키가 없으면 관리자 승인으로 대체.
- 부서 12개 고정 시드, 기존 `HR` 부서는 `HR본부`로 개명.
- 폰(게이트웨이)은 부서에 1:1로 연결된다. 폰이 없는 부서의 직원은 문자를 보낼 수 없고 안내가 나온다(관리자가 폰을 연결/부서 이동).

## 2026-10-15 운영 안정성 1단계
- 폰 상태 점검(5분)·장애/복구 메일, 오류 급증 메일, `/healthz` DB 확인, 안전 배포 스크립트(마이그레이션 선행), 백업 스크립트와 Time Travel 복구 절차, GitHub Actions CI.
- 폰 상태 신호는 서버의 `lastSeen` 이다. 폰이 유휴면 갱신이 드물어 `warn` 이 잦을 수 있어, 메일은 2시간 초과(`down`)에만 보낸다. 앱 Ping 간격 설정을 권장.
- 한계: 발송 요청이 서버에 접수(202)된 것만 "보냄"으로 기록한다. 실제 전달 결과(`delivered`)는 2단계에서 반영한다.

## 2026-10-15 운영 안정성 2단계: 전달 결과 · 자동 재시도 · 새 답장 알림
- 발송 응답의 메시지 id(`gw_msg_id`)를 저장하고, 웹훅(`sms:sent|delivered|failed`)과 2분 주기 서버 조회로 전달 상태를 반영한다. 웹훅 등록은 이벤트 4종.
- 재시도: 총 3회(2분, 10분 간격), 영구 오류(400/401/403/404/422)는 즉시 실패. 전달 실패 이벤트도 같은 정책으로 재시도하며, 완료된 캠페인은 다시 `sending` 으로 돌린다.
- 답장을 이미 한 사람의 전달 실패 이벤트는 상태를 바꾸지 않는다(회신이 더 강한 증거).
- 새 답장 메일은 **내용·번호 없이 링크만**, 사용자별 선택(기본 꺼짐), 5분에 1회. 안 읽은 문자는 부서 공유 받은편지함 기준(`inbound.read_at`).
- **한계(운영 시험으로 확인)**: 이 환경에서는 서버 상태가 `Sent` 에서 `Delivered` 로 바뀌지 않았다(통신사 전달 확인 없음). "전달됨"은 전달 확인이 오는 환경에서만 표시된다.

## 폰 설치는 처음부터 Obtainium 으로 (2026-10)
- 최신 안드로이드(13+)는 GitHub 에서 직접 받은 APK 의 문자 권한을 "제한된 설정"으로 막고, 삼성 자동 차단·Play 프로텍트도 설치를 막는다.
- 그래서 안내를 **설치 전 막힘 해제 → Obtainium 설치 → Obtainium 으로 SMSGate(`app-release.apk`) 설치 → 권한(막히면 제한된 설정 허용) → RCS 끄기 → 배터리 제한 없음 → 서버/암호화 → 켜기 → 아이디·비밀번호 옮기기(9단계)** 로 바꿨다. `app-insecure.apk`/`.aab` 는 쓰지 않는다.
- 단계 본문은 `src/pages-help.js` 한 곳에서 관리하며 설정 화면과 `/help/phone`(모든 로그인 사용자, 토큰은 관리자만) 이 같이 쓴다.

## 면접 결과·자동 리마인드 (2026-10)
- 아웃소싱 채용 관점 검토에서 "참석 답장 이후"가 비어 있었다. 후보자 행에 `outcome`(showed/noshow/passed/hired/rejected)을 추가하고 출석률·노쇼를 집계한다.
- 자동 리마인드는 면접일시 글자를 `parseInterviewAt`으로 읽어 면접 당일 08:00(KST)부터 면접 시각 전까지 1회(`reminded_at`) 보낸다. 직접 문자 큐(`messages`)를 쓰므로 재시도·전달 추적이 그대로 적용된다. 기존 안내는 마이그레이션 0010에서 꺼 둔다.
- 남은 후보: 지원자 인력풀(이력 연결), 사업장 마스터, 답장 처리함, 발송 용량 계획.

## 지원자·블랙리스트 모듈 (2026-10)
- 문자 시스템과 **별개 모듈**(별도 테이블: applicants, applicant_applications, blacklist, applicant_events). 발송 차단 기능이 아니다.
- 사유는 정해진 목록 + 기타(사유 필수). 자동 만료 없이 수동 해제. 권한은 일단 로그인한 모두, 이후 전체 관리자로 제한 예정(`canUseApplicants`).
- 문자 시스템 연결은 선택(기본 미연결): 자동 등록, 이력 가져오기, 노쇼 후보 제안, 참고 표시 — 항목별 스위치로 이후 단계에서 추가.

- 연결(2026-10): 기본 꺼짐, 관리자만 설정. 항목별 스위치(자동 등록 / 이력 / 노쇼 후보 제안 / 참고 표시). 어떤 항목도 발송을 막지 않는다. 노쇼 제안 기준 기본 3회. 이력은 부서 권한 범위 안에서만 보인다.
