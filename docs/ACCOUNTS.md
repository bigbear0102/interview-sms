# 계정 · 회원가입 · 권한

## 한눈에 보기

| 항목 | 내용 |
|---|---|
| 로그인 | **이메일 + 비밀번호** |
| 가입 | 직원 누구나 `/signup` — 이름, 이메일, 휴대폰번호, 부서, 비밀번호 |
| 이메일 제한 | **`@willvi.co.kr`** 로 끝나는 주소만 (`ALLOWED_EMAIL_DOMAIN`) |
| 인증 | 가입 시 인증 메일 발송 → 링크 클릭(24시간, 1회용) → 로그인 가능 |
| 권한 | **관리자**(모든 것 수정) / **일반 사용자**(가입 때 고른 부서의 폰·면접 안내·문자만) |
| 부서 | 임원실, 경영지원본부, 마케팅영업본부, CRM운영본부, 물류사업본부, 윌비모터스, HR본부, FM사업부문, IT사업본부, 지사, 동부캐리어, 센터 |

## 가입 흐름

```
/signup 작성 ─▶ 검증(도메인·휴대폰·비밀번호·부서) ─▶ 계정 생성(인증 전, 로그인 불가)
            ─▶ 인증 메일 ─▶ /verify?token=… ─▶ 활성화 ─▶ 로그인
```

- 인증 전에 로그인하면 "이메일 인증이 필요해요" 화면에서 인증 메일을 다시 받을 수 있다.
- 비밀번호를 잊으면 `/forgot` → 메일의 링크 → `/reset`.
- **메일 발송이 설정되지 않았을 때**: 가입은 접수되고 "관리자에게 승인을 요청"이라고 안내한다.
  관리자는 설정 → 사용자의 **승인하기**로 인증 없이 활성화할 수 있다.

## 관리자가 할 수 있는 일 (설정 화면)

- 사용자: 직접 추가(인증 건너뜀), **이름·이메일·휴대폰·권한·부서 수정**, 비밀번호 바꿔주기, 쓰지 못하게/다시, **삭제**, 인증 대기자 **승인**
- 부서: 추가, **이름 바꾸기**, 삭제(연결된 사용자·폰·면접 안내가 없을 때)
- 문자 보내는 폰: 이름·소속 부서 수정, 연결 확인, 받기 시험, 다시 설치 시 계정 변경, 쓰지 않기
- 모든 부서의 면접 안내·문자함을 볼 수 있다. (일반 사용자는 자기 부서만)
- 자기 자신은 삭제/사용 중지할 수 없다.

## 보안 설계

- 도메인 검사는 서버에서 정확히 일치만 허용한다 (`a@gmail.com`, `a@willvi.co.kr.evil.com`, `a@mail.willvi.co.kr`, `a@willvi.co.kr@evil.com` 모두 거부 — 테스트로 고정).
- 인증/재설정 토큰: 32바이트 난수, **해시만 저장**, 1회용, 만료(인증 24시간, 재설정 1시간).
- 횟수 제한: 가입(IP 10회/시간, 이메일 5회/시간), 메일 재발송(이메일 3회/시간), 재설정 요청, 로그인 실패 5회 → 5분 잠금.
- 존재 여부를 알려 주지 않는다: 이미 가입된 메일로 가입하거나, 없는 메일로 재설정을 요청해도 같은 응답.
- 비밀번호는 PBKDF2-SHA256(100k)로 저장, 재설정 시 기존 로그인 세션을 모두 끊는다.
- 이전 방식의 아이디(`admin`)는 **이메일이 등록되지 않은 계정에 한해** 로그인에 쓸 수 있다. 설정에서 이메일을 등록하면 이메일로만 로그인한다.

## 메일 발송 설정 (현재: Resend, BBform 과 같은 설정 재사용)

**현재 운영 설정**: Resend API(발송 전용 키) + 발신 `문자 관리 <no-reply@mail.bigbears.me>`. BBform 프로젝트(`projects/bbform`, `src/lib/email.ts`)에서 쓰던
Resend 계정과 인증된 발신 도메인 `mail.bigbears.me`를 그대로 사용한다. 시크릿 `RESEND_API_KEY`는 Worker 에 등록되어 있고
`MAIL_FROM`은 `wrangler.jsonc` 변수다. (발송 시험: Resend 시험 수신 주소로 `ok:true` 확인)

> 주의: 발신 도메인이 `bigbears.me` 계열이라 `@willvi.co.kr` 메일함에서 **스팸함으로 분류**될 수 있다. 처음 가입 시험 때 스팸함을 확인하고,
> 계속 스팸 처리되면 IT팀에 `no-reply@mail.bigbears.me` 허용(또는 `willvi.co.kr` 쪽 발신 도메인 인증)을 요청한다.

### 다른 방식으로 바꾸려면

인증 메일을 보내려면 아래 중 **하나**를 설정한다. (`src/mailer.js`)

| 방식 | 설정 | 비고 |
|---|---|---|
| **Resend** (권장, 간단) | 시크릿 `RESEND_API_KEY`, 변수 `MAIL_FROM` | 발신 도메인 DNS 인증 필요. 무료 한도 있음 |
| Cloudflare Email Sending | `send_email` 바인딩 `EMAIL`, 변수 `MAIL_FROM` | 베타, **Workers 유료 플랜** 필요, 도메인 온보딩 필요 |
| 사내 메일 서버 연동 | `MAIL_SEND` 함수 주입(코드 수정) | Node 서버로 옮긴 뒤 SMTP 연결 시 |

```bash
npx wrangler secret put RESEND_API_KEY      # Resend API 키
# wrangler.jsonc vars 에: "MAIL_FROM": "문자 관리 <noreply@발신도메인>"
npm run deploy
```

발신 주소는 SPF/DKIM 이 설정된 도메인이어야 사내 메일(`@willvi.co.kr`)에서 스팸으로 분류되지 않는다.
가능하면 `willvi.co.kr` 도메인(또는 그 하위)에서 발송하도록 IT 팀과 협의한다.

## 데이터

`users`: `name`, `email`(유일), `phone`, `email_verified_at`, `created_at` 추가 (`migrations/0007_accounts.sql`).
`email_tokens`(인증/재설정 토큰 해시), `rate_limits`(횟수 제한). 부서 12개는 마이그레이션에서 시드하고, 기존 `HR` 부서는 `HR본부`로 이름을 맞춘다.
